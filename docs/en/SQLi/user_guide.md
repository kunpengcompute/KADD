This document describes how to configure the KADD SQL injection detection engine and provides code examples.



## Configuration File

KADD configures each engine module through `config.json`.

```json
{
  "engine_mode": "ml",

  "transition_table": "/opt/KADD/SQLi/assets/data/transition_table.bin",
  "output_table": "/opt/KADD/SQLi/assets/data/output_table.bin",
  "eod_table": "/opt/KADD/SQLi/assets/data/eod_table.bin",

  "model_rf": "/opt/KADD/SQLi/assets/model/model_tokens_rf.krf",
  "model_rf_onnx": "/opt/KADD/SQLi/assets/model/model_tokens_rf.onnx",

  "model_cnn": "/opt/KADD/SQLi/assets/model/model_tokens_dl_cnn.kcn",
  "model_cnn_onnx": "/opt/KADD/SQLi/assets/model/model_tokens_dl_cnn.onnx"
}
```

### Parameter Description

| Parameter | Description | Optional Value |
|------|------|--------|
| `engine_mode` | Inference mode | `ml` (Random Forest)/`dl` (CNN) |
| `transition_table` | DFA state transition table path | Default |
| `output_table` | DFA output table path | Default |
| `eod_table` | DFA EOD table path | Default |
| `model_rf` | RF native model path (`.krf`) | Default |
| `model_rf_onnx` | RF ONNX model path (`.onnx`) | Default |
| `model_cnn` | CNN native model path (`.kcn`) | Default |
| `model_cnn_onnx` | CNN ONNX model path (`.onnx`) | Default |

### Inference Mode Description

- **ML mode** (default): uses a Random Forest classifier. When SVE is available, it preferentially loads the native `.krf` format; upon failure, it falls back to ONNX Runtime to load the `.onnx` format.
- **DL mode**: uses a CNN deep learning model. When SVE is available, it preferentially loads the native `.kcn` format; upon failure, it falls back to ONNX Runtime to load the `.onnx` format.
- **Model authentication**: Native `.krf`/`.kcn` models enforce HMAC-SHA256 authentication. Unsigned models, missing keys, or mismatched keys result in load rejection (fail-closed) and in this case, models fall back to ONNX. `.onnx` models do not participate in authentication.



## Prerequisites

You have completed installation by following instructions in [Installation Guide](installation_guide.md).

Before loading a native model (`.krf`/`.kcn`), you must also inject the model HMAC key.

```bash
export KADD_MODEL_HMAC_KEY=74fab58d87dc235ee049b6faf21b44825dba1d9dc05bbc14aeded49cb211a1db
```

You can also directly source the environment file generated by `build.sh` (which also contains the library search path).

```bash
source /opt/KADD/SQLi/build/kadd_env.sh
```

![note icon](../../public_sys-resources/icon-note.gif) **NOTE:**

- The key above is the public **development key** bundled with the repository, intended only for building, testing, and feature evaluation. For production deployment, you must re-sign the model with your own key using `tools/rf_sign/rf_sign.py` and inject it through KMS or an env file with restricted permissions.
- When no key is injected, the native model is rejected from loading and an ERROR is printed to stderr, after which it falls back to ONNX (losing SVE acceleration); programs that directly call `kadd_rf_model_load()`/`kadd_cnn_model_load()` will fail to load.

### Performance Tuning: ONNX Runtime Thread Count

During fallback to ONNX Runtime, the engine explicitly sets `intra_op=8` and `inter_op=1` when creating the session, for the following reasons:

- The model is very small (`batch` ≤ `64`; `feature_dim` = `300`). ONNX Runtime opens threads based on the physical core count by default, so the thread dispatch and synchronization overhead far exceeds the operator computation itself.
- Measured CNN batch throughput is only about 1600 samples/second; after the ONNX threads are fixed to `8`, the throughput recovers to about 14,000 to 18,000 samples/second.

If you need to tune it per device model, you can override it with environment variables, without recompilation.

```bash
export KADD_ORT_INTRA_OP_THREADS=8   # Value range 1-1024; invalid values are ignored and fall back to the default value 8.
export KADD_ORT_INTER_OP_THREADS=1   # Value range 1-1024; invalid values are ignored and fall back to the default value 1.
```

![note icon](../../public_sys-resources/icon-note.gif) **NOTE:**

- The thread count only affects performance, not detection results; when the value is invalid, only a WARN is printed and the default value is used, which does not cause model loading to fail.
- The environment variables are read when the engine instance is created; after modification, the engine must be recreated for the changes to take effect.
- `coverage_all.sh` exports the above two variables by default (`8`/`1`). You can temporarily tune them by running `KADD_ORT_INTRA_OP_THREADS=4 ./coverage_all.sh`.



## Complete SQL Injection Detection Cases

### Case 1: Real-Time Detection for Web Applications

#### Complete code: `web_detection_app.c`

The sample program operates in the following order:

1. Creates the engine.
2. Simulates user-input detection. The input includes normal input and SQL injection attacks.
3. Detects each input one by one and outputs the result by probability.
4. Cleans up resources.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include "kadd_sqli_engine.h"
#include "kadd_errors.h"

int main() {
    kadd_sqli_engine_t *engine = NULL;
    int ret = kadd_sqli_engine_create_from_file(&engine, "/opt/KADD/SQLi/config.json");
    if (ret != KADD_SUCCESS) {
        fprintf(stderr, "Engine creation failed: %d\n", ret);
        return -1;
    }

    const char *user_inputs[] = {
        "id=1",
        "name=John",
        "id=1' OR '1'='1",
        "admin'--",
        "SELECT * FROM users"
    };

    for (int i = 0; i < 5; i++) {
        float probability = 0.0f;
        ret = kadd_sqli_detect(engine, user_inputs[i], &probability);

        if (ret == KADD_SUCCESS) {
            if (probability >= 0.5f) {
                printf("[Attack] Input: \"%s\" (Probability: %.2f%%)\n",
                       user_inputs[i], probability * 100);
            } else {
                printf("[Safe] Input: \"%s\" (Probability: %.2f%%)\n",
                       user_inputs[i], probability * 100);
            }
        }
    }

    kadd_sqli_engine_free(engine);
    return 0;
}
```

#### Compilation and Running

1. Compile the program.

    ```bash
    gcc -o web_detection_app web_detection_app.c \
        -I/opt/KADD/SQLi/include \
        -L/opt/KADD/SQLi/build/src \
        -lkadd_sqli_engine -lkadd_dl_engine -lkadd_ml_engine \
        -lkadd_cnn_engine -lkadd_rf_engine -lkadd_inference_engine \
        -lkadd_feature_engine -lkadd_dfa_engine -lkadd_config_loader
    ```

2. Set the library search path and the model HMAC key, and then run the program.

    ```bash
    export LD_LIBRARY_PATH=/opt/KADD/SQLi/build/src:/opt/KADD/SQLi/util/onnxruntime-linux-aarch64-1.28.0/lib:$LD_LIBRARY_PATH
    # Development key. Replace it with your own key in production environments.
    export KADD_MODEL_HMAC_KEY=74fab58d87dc235ee049b6faf21b44825dba1d9dc05bbc14aeded49cb211a1db
    ./web_detection_app
    ```

##### Expected Output

```bash
[Safe] Input: "id=1" (Probability: 0.02%)
[Safe] Input: "name=John" (Probability: 0.01%)
[Attack] Input: "id=1' OR '1'='1" (Probability: 98.54%)
[Attack] Input: "admin'--" (Probability: 95.21%)
[Attack] Input: "SELECT * FROM users" (Probability: 87.33%)
```



### Case 2: Batch Log Analysis

#### Complete code: `log_analysis_app.c`

The sample program operates in the following order:

1. Creates the engine.
2. Prepares the batch log data.
3. Performs batch detection and outputs the attack logs.
4. Cleans up resources.

```c
#include <stdio.h>
#include "kadd_sqli_engine.h"
#include "kadd_errors.h"

int main() {
    kadd_sqli_engine_t *engine = NULL;
    if (kadd_sqli_engine_create_from_file(&engine, "/opt/KADD/SQLi/config.json")
            != KADD_SUCCESS) {
        return -1;
    }

    const char *log_entries[] = {
        "[2024-01-01 10:00:00] GET /api/user?id=123",
        "[2024-01-01 10:00:05] POST /login user=admin&pass=test",
        "[2024-01-01 10:00:10] GET /search?q=cat' OR '1'='1",
        "[2024-01-01 10:00:15] POST /update id=1; DROP TABLE users--"
    };
    int log_count = 4;
    float probabilities[log_count];

    int ret = kadd_sqli_detect_batch(engine, log_entries, log_count,
                                      probabilities, 64);

    if (ret >= 0) {
        printf("Batch detection results: \n");
        for (int i = 0; i < log_count; i++) {
            if (probabilities[i] >= 0.5f) {
                printf("[Attack] Log %d: Attack detected (%.2f%%)\n", i+1, probabilities[i] * 100);
                printf("   Content: %s\n", log_entries[i]);
            }
        }
    }

    kadd_sqli_engine_free(engine);
    return 0;
}
```

#### Compilation and Running

1. Compile the program.

    ```bash
    gcc -o log_analysis_app log_analysis_app.c \
        -I/opt/KADD/SQLi/include \
        -L/opt/KADD/SQLi/build/src \
        -lkadd_sqli_engine -lkadd_dl_engine -lkadd_ml_engine \
        -lkadd_cnn_engine -lkadd_rf_engine -lkadd_inference_engine \
        -lkadd_feature_engine -lkadd_dfa_engine -lkadd_config_loader
    ```

2. Before running, set the library search path and the model HMAC key (including the KADD dynamic library and ONNX Runtime), and then run the program.

    ```bash
    export LD_LIBRARY_PATH=/opt/KADD/SQLi/build/src:/opt/KADD/SQLi/util/onnxruntime-linux-aarch64-1.28.0/lib:$LD_LIBRARY_PATH
    # Development key. Replace it with your own key in production environments.
    export KADD_MODEL_HMAC_KEY=74fab58d87dc235ee049b6faf21b44825dba1d9dc05bbc14aeded49cb211a1db
    ./log_analysis_app
    ```

##### Expected Output

```bash
Batch detection results: 
[Attack] Log 3: Attack detected (83.04%)
Content: [2024-01-01 10:00:10] GET /search?q=cat' OR '1'='1
[Attack] Log 4: Attack detected (79.58%)
Content: [2024-01-01 10:00:15] POST /update id=1; DROP TABLE users--
```
